# ShrinkFlow v1.2.0 — 作品集介绍

## 产品背景

ShrinkFlow 是一款桌面端视频批量压缩工具，面向有批量视频处理需求的用户：视频创作者、内容运营、摄影师、普通用户。

当前版本（v1.2.0）的核心创新是引入了 **Smart Shrink Plan** —— 一个可解释的规则引擎，能够分析每个视频的编码特征，为每个文件独立推荐最优压缩策略。

## 用户痛点

**痛点 1：一刀切压缩**
现有工具对所有视频使用相同的压缩参数。一个已经高度压缩的 HEVC 视频会被再次压缩（浪费时间，可能损坏画质），而一个码率超高的 ProRes 素材却只用了温和参数（空间没省多少）。

**痛点 2：不安全的覆盖**
很多工具压缩后直接覆盖原文件。如果压缩后文件反而变大，或者画质严重下降，用户无法恢复原始文件。

**痛点 3：技术门槛高**
FFmpeg 命令行参数复杂（CRF、preset、编码格式、像素格式），普通用户根本不知道该设什么值。在线工具需要上传隐私视频，存在安全风险。

## 产品定位

**ShrinkFlow 是一款元数据感知的桌面端视频批量压缩工具。它用可解释的规则引擎分析每个视频的编码特征，为每个文件独立推荐最优压缩策略，让普通用户无需理解 CRF、码率、编码格式，也能完成批量压缩决策。**

核心理念：压缩参数（CRF、preset、编码格式）是手段，不是目的。用户关心的是"省多少空间"和"画质会不会变差"，不是"CRF 应该设 21 还是 25"。ShrinkFlow 替用户做参数决策，同时让决策过程可解释、可覆盖。

## 核心卖点

### 卖点 1：Per-Video 智能决策

每个视频独立分析，独立推荐。一个批次里可能有 3 个视频推荐重度压缩、5 个跳过、2 个需要确认。

技术实现：6 层规则引擎（硬排除 → 编码分类 → 证据收集 → 目标决策 → 高风险降级 → 低收益过滤），基于 BPPF（bits-per-pixel-per-frame）和编码效率分级。

### 卖点 2：三级策略目标

用户只需选择一个目标强度：
- **安全优化**（CRF 20 / slow）—— 只压缩明显值得处理的视频
- **智能推荐**（CRF 21 / medium / yuv420p）—— 平衡收益与风险
- **空间优先**（CRF 25 / medium / yuv420p）—— 优先省空间，高风险需确认

切换目标后，所有视频重新分类。

### 卖点 3：可解释的决策

每个建议附带 reason code（共 17 种），如 `already_compressed`、`efficient_codec`、`low_return`、`high_bitrate`。用户能看到"为什么这个视频被跳过"或"为什么需要确认"，而不是面对一个黑盒。

### 卖点 4：四重安全保护

1. **输出变大保护** —— 压缩后文件 ≥ 原始大小，自动跳过替换
2. **原子替换** —— 备份 → 替换 → 删除备份，失败自动回滚
3. **高风险确认** —— 高效编码重压缩、低 BPPF、极端压缩比自动降级为"需确认"
4. **低收益过滤** —— 预估节省不到阈值的视频自动跳过

### 卖点 5：本地离线，开箱即用

FFmpeg 内嵌，零外部依赖，零遥测。所有处理在本地完成，隐私视频不离开用户电脑。

## 技术架构亮点

**三进程架构：** Electron 主进程（36 个 IPC handler）+ Preload 桥接 + React 渲染进程。contextIsolation 启用，nodeIntegration 禁用。

**纯 TS 决策引擎：** `smart-shrink/` 模块是纯 TypeScript，无副作用，可在单元测试中独立验证。6 层分类架构，17 种 reason code，BPPF 5 档分级。

**状态管理：** Zustand store + sessionId 防止异步回调中的过期结果污染 UI。队列级/视频级/状态回归三重保护。

**原子文件操作：** 备份-替换策略，跨设备 fallback 到 copyFile + unlink，失败自动回滚。

**FFmpeg 生命周期：** 三源解析（bundled > updated > system），metadata.json 版本追踪，atomic replace 更新。

## 关键迭代过程

**v0.1.0 → v1.2.0 的核心升级：**

1. **从全局模式到 per-video mode：** v0.1.0 所有视频用同一压缩模式。v1.2.0 引入规则引擎，每个视频独立推荐。

2. **从手动选择到智能推荐：** v0.1.0 用户需要自己判断该用哪个模式。v1.2.0 用户只需选择目标强度（轻度/中度/重度），系统完成剩余决策。

3. **数据源一致性修复：** Smart Plan 的 summary 和视频列表筛选使用了不同数据源——summary 来自 useMemo，视频的 shrinkAdvice 来自 store。切换目标后两者不同步。通过统一为 `adviceByVideoId` Map 作为 single source of truth 解决。

## v0.3 规划

1. **Smart Probe** —— 5 秒快速试压，获取实际编码速度和输出比例
2. **历史反馈学习** —— 用过去压缩结果修正未来估算
3. **质量评估** —— SSIM/PSNR 量化画质变化

## 面试讲述要点

这个项目体现了以下产品能力：

1. **把规则引擎融入用户流程** —— 不是独立的分析工具，而是嵌入批量压缩流程的决策系统。用户感知不到引擎的存在，但每个决策都是引擎驱动的。

2. **平衡自动化和可控性** —— "自动决策 + 透明展示 + 随时覆盖"的交互模式。用户可以一键执行，也可以逐个审查。

3. **可解释性优先** —— 17 种 reason code 让每个决策透明。用户能理解"为什么"，才能信任"建议"。

4. **安全优先** —— 四重保护确保"不损坏"是第一优先级。

5. **复杂状态协同** —— Smart Plan、队列进度、筛选逻辑、历史记录、压缩配置通过 Zustand + sessionId 机制保证一致性。
