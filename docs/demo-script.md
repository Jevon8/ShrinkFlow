# ShrinkFlow Demo 演示脚本

> 用于录屏演示或面试现场演示，时长控制在 3-5 分钟。

---

## 完整演示脚本（3-5 分钟）

### 第 1 步：开场介绍（20 秒）

**操作：** 打开 ShrinkFlow 应用，展示首页空状态

**话术：**
> "这是 ShrinkFlow，一个基于 Electron + FFmpeg 的桌面端批量视频压缩工具。它的核心目标是让普通用户也能轻松完成批量视频压缩，不需要了解 FFmpeg 的复杂参数。接下来我用 3 分钟演示一下核心功能。"

**屏幕展示：** 应用首页，空状态，左侧导航栏显示压缩、历史、设置三个页面

---

### 第 2 步：添加视频（30 秒）

**操作：** 点击"选择文件"按钮，选择 2-3 个视频文件

**话术：**
> "添加视频有三种方式：点击按钮选择文件、直接拖拽文件到窗口、或者选择整个文件夹递归扫描。我现在选择几个视频文件。"

**屏幕展示：** 文件选择对话框 → 选择视频文件 → 返回应用，视频列表显示文件名、大小、状态为"分析中"

---

### 第 3 步：拖拽文件夹（20 秒）

**操作：** 从资源管理器拖拽一个包含视频的文件夹到应用窗口

**话术：**
> "也可以直接拖拽整个文件夹，应用会自动递归扫描所有子目录中的视频文件，自动去重和跳过非视频文件。"

**屏幕展示：** 拖拽文件夹 → 扫描进度提示 → 视频列表更新，显示更多文件

---

### 第 4 步：查看视频信息（20 秒）

**操作：** 展示视频列表中的元信息列

**话术：**
> "每个视频都会自动分析元信息，包括时长、分辨率、编码格式、码率、帧率。这些信息帮助用户了解视频的基本情况，也用于后续的压缩计划生成。"

**屏幕展示：** 视频列表，显示时长（如 00:05:30）、分辨率（如 1920x1080）、编码（如 h264）、码率（如 8500 kbps）

---

### 第 5 步：选择默认模式压缩（30 秒）

**操作：** 保持默认的"兼容高质量"模式，点击"开始压缩"

**话术：**
> "默认使用兼容高质量模式，CRF 21，yuv420p 像素格式，确保最大兼容性。点击开始压缩后，可以看到每个文件的实时进度，包括百分比、编码速度和预估剩余时间。"

**屏幕展示：** 压缩进度界面，显示当前文件进度条、整体进度条、速度（如 2.5x）、ETA（如 剩余 3 分钟）

---

### 第 6 步：使用 Target Size Accurate（40 秒）

**操作：** 停止当前压缩（或等待完成），选择"Target Size Accurate"模式，设置目标大小为 100MB，开始压缩

**话术：**
> "现在演示 Target Size Accurate 模式。用户最常见的需求是'我想把这个视频压缩到 100MB 以内'。这个模式使用 two-pass 编码，第一次分析内容复杂度，第二次精确分配码率，文件大小偏差可以控制在 5% 以内。"

**屏幕展示：** Target Size 面板，输入目标大小 100MB → 开始压缩 → 显示 Pass 1/2 阶段提示 → 进度条分为两段（0-50% 和 50-100%）

---

### 第 7 步：展示 two-pass 阶段提示（20 秒）

**操作：** 在 two-pass 压缩过程中，展示阶段提示

**话术：**
> "Two-pass 压缩会显示当前是第几阶段。Pass 1 分析视频内容复杂度，Pass 2 根据分析结果精确分配码率。进度条分为两段，前半段是 Pass 1，后半段是 Pass 2。虽然比单次编码慢，但文件大小控制更精确。"

**屏幕展示：** 进度界面，显示"Pass 1/2"或"Pass 2/2"标识，进度条分段显示

---

### 第 8 步：展示压缩完成状态（20 秒）

**操作：** 等待压缩完成，展示结果汇总

**话术：**
> "压缩完成后，可以看到每个文件的结果：原始大小、压缩后大小、节省百分比、实际耗时。整体汇总显示总共节省了多少空间。"

**屏幕展示：** 压缩完成状态，视频列表显示绿色完成标识，每个文件显示压缩前后大小对比（如 2.1GB → 485MB，节省 77%）

---

### 第 9 步：展示历史记录（30 秒）

**操作：** 点击左侧导航"历史"，展示历史记录页面

**话术：**

**屏幕展示：** 历史记录列表，显示多条记录，每条显示时间、文件数、大小变化、耗时

---

### 第 10 步：导出 CSV（20 秒）

**话术：**

**屏幕展示：** 系统保存对话框 → 选择位置 → 保存成功提示

---

### 第 11 步：展示 FFmpeg 管理（30 秒）

**操作：** 点击左侧导航"设置"，展示 FFmpeg 状态区域

**话术：**

## 60 秒简短版演示话术

> 这是 ShrinkFlow，一个基于 Electron + FFmpeg 的桌面端批量视频压缩工具。
>
> 核心功能有三个：
>
> 第一，批量压缩。支持拖拽文件夹递归扫描，自动去重，串行队列处理，单文件失败不影响整体。
>
> 第二，精确控制。除了常规的平衡、质量优先、最小体积模式，还有 Target Size 模式。Fast 模式单次编码快速出结果，Accurate 模式通过 two-pass 精确控制文件大小，偏差在 5% 以内。
>
> 第三，数据安全。替换原文件时使用 backup-then-swap 策略，先备份、再替换、成功后删除备份，失败自动回滚，确保不会丢失原始数据。
>
> 此外还有三层 ETA 预估系统、压缩历史记录和导出、内嵌 FFmpeg 和应用内更新。
>
> 技术栈是 Electron + React + TypeScript + Zustand + Tailwind CSS，138 个测试用例，可以打包成 Windows 安装程序。
>
> 这个项目展示了从需求分析、产品设计到工程落地的完整能力。谢谢。

## 演示注意事项

### 准备工作

1. 确保 `npm run dev` 已启动，应用正常运行
2. 准备 3-5 个不同大小的视频文件（建议 100MB-1GB）
3. 准备一个包含多个视频的文件夹（用于演示递归扫描）
4. 清空历史记录（确保演示时历史页面是空的或只有演示数据）
5. 确保 FFmpeg 可用（开发模式需要系统 PATH 中有 FFmpeg）

### 演示技巧

- **不要等待真实压缩完成** — 可以提前准备好已完成的压缩结果，或者压缩一个很小的视频（如 10MB）
- **提前测试拖拽** — 确保拖拽功能在录屏环境下正常工作
- **准备备用方案** — 如果某个功能出问题，可以跳过或展示截图
- **控制节奏** — 每个步骤不要太快，让观众看清楚操作和结果

### 常见问题应对

- **如果压缩速度太慢** — 使用小视频文件，或提前压缩好展示结果
- **如果 FFmpeg 不可用** — 展示设置页面的 FFmpeg 状态，说明内嵌机制
- **如果拖拽不工作** — 使用文件选择按钮作为备用方案
